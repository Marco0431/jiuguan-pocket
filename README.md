# 酒馆口袋 · Jiuguan Pocket

**校园晚上断了外网，电脑上的酒馆还能借手机流量继续用，不用开热点。**

这个项目来自一个很具体的需求：酒馆和聊天记录都在电脑上，校园网夜间断网后电脑调不了 API；把整套酒馆搬到手机上运行又比较吃力，也不想每晚开热点、给电脑换网络。

酒馆口袋由 **安卓客户端 + SillyTavern 服务端插件**组成。电脑继续运行酒馆、保存角色卡和聊天数据；手机连着原来的局域网 Wi-Fi，同时用移动数据为酒馆提供外网出口。手机只需要安装一个轻量客户端，选择「使用手机流量」。

> **前提：断的是外网，手机和电脑之间的局域网仍然互通。** 如果学校同时关闭 Wi-Fi、断开内网，或启用了设备隔离，手机无法访问电脑，本方案也无法连接。无需开启手机热点。

普通下载版：**1.3.2**；最新预发布为 **1.3.3 诊断测试版**，适用于 Android 8.0 及以上。项目处于早期测试阶段。

## 怎么连接

```text
手机 App ── 局域网 Wi-Fi ── 电脑上的 SillyTavern
   │                            │
   │                      酒馆插件把外网请求交给手机
   │                            │
   └── 手机移动数据 ── API / 公网资源
```

酒馆服务和数据在电脑，**网页仍由手机 WebView 渲染**。它减少了在手机上运行酒馆服务的负担，也省去了普通浏览器的地址栏；不是远程桌面，不能保证消除复杂前端、长聊天记录带来的所有卡顿。

## 第一次使用

### 电脑：装一次插件

1. 准备已经安装好依赖、能正常启动的 SillyTavern。Node.js 需要支持运行时代理切换，例如 **24.14+ 或 25.4+**，安装器会检查。
2. 解压电脑插件 ZIP，双击 `安装酒馆插件.cmd`，按提示选择包含 `server.js` 的 SillyTavern 目录。
3. 完成后重启酒馆一次。以后照常使用原来的 `Start.bat`，不需要额外打开中转启动器。

安装器会备份原文件、启用服务端插件，并调整已知的 `Start.bat`：依赖已安装时跳过启动前的 npm 安装，方便电脑离线启动。它还会关闭服务端插件的启动时自动更新。依赖安装和必要的更新请提前在有网时完成。

详细变更、安装检查和恢复方式见 [插件安装说明](tools/SERVER-PLUGIN-INSTALL.md)。只用电脑原有网络时，可以不安装此插件。

### 手机：选网络，填地址

1. 安装 APK，连接电脑所在的局域网 Wi-Fi。
2. 在配置页选择联网方式：

   | 选项 | 什么时候用 |
   | --- | --- |
   | **使用电脑网络** | 电脑自己可以访问模型 API 和所需网站 |
   | **使用手机流量** | 电脑只有内网；手机同时开启 Wi-Fi 和移动数据 |

3. 填写手机浏览器能够打开的酒馆地址，例如 `http://192.168.1.100:8000`，然后点「打开酒馆」。示例地址需要替换成自己的电脑 IP 和端口。
4. 使用酒馆原有账号登录。手机流量模式会自动连接电脑插件，不需要复制代理地址或配对密钥；多用户酒馆需要管理员账号。
5. 保持「后台保持」开启，允许通知，并按手机系统提供的选项允许后台运行。遇到“此 Wi-Fi 无法上网”的提示时，选择继续连接这个 Wi-Fi。

成功连接后，下次打开 App 会按上次成功的配置自动进入。失败或取消会回到配置页，不会反复自动重连。网络和网页准备有约 15 秒超时；填写 Basic 登录框时暂停计时，自动启动的插件确认额外最多等待约 6 秒。

## 日常使用

- **记住密码和自动登录**：HTTP Basic 账号密码使用 AndroidKeyStore 管理的密钥加密保存，可关闭自动登录或清除。自动进入与自动提交账号密码是两个独立功能。
- **随时改设置**：网页右侧「连接设置」可以修改地址和网络模式；仅查看设置不会重载网页。「更多」→「连接方式」也能直接切换网络。建议在当前回复结束后切换。
- **尽量保持后台回复**：前台服务保留同一个 WebView，切到后台时不会主动刷新页面或暂停网页计时器；通知里可以停止并断开。
- **导入导出**：使用系统文件选择器导入角色卡等文件；支持 Blob / data 导出，单文件上限 16 MiB。
- **失败后自己决定重试**：不会自动重发模型生成请求，避免重复生成和额外 API 消耗。

## 能打开酒馆，但模型列表或发送失败

“手机与电脑已连接”只表示配对和代理设置完成，不能证明手机能访问所选 API。单独的 `Bad Request` 也不足以判断出错环节。

1.3.3 增加了「连接诊断」。同时更新手机 APK 和电脑插件并重启酒馆后，先重现一次失败，再从「更多」→「连接诊断」→「刷新」→「复制诊断」取得报告。配置页也有诊断入口，读取诊断不会发送模型请求。

报告区分手机 DNS／TCP 失败、电脑代理连接失败和上游 HTTP 响应。它只包含网络状态、目标域名、状态码和计数，不包含账号密码、API 密钥、URL 路径、请求头或聊天正文。隧道建立成功只代表 TCP 可达；上游返回 400 时，还需要核对 API 配置或服务端报错。

本版修正了公网地址重试可能超过电脑等待上限的问题：IPv4/IPv6 交错尝试，每次最多 3 秒、最多 4 个地址，DNS 耗时计入 12 秒连接预算。系统 DNS 调用本身不能强制限时。此修正尚不能证明已解决所有 `Bad Request`，仍需实际手机网络上的诊断结果。

## 适用范围

手机模式覆盖酒馆标准 HTTP/HTTPS 请求、聊天 API、资源下载、Node 原生 `fetch`、继承代理环境的 Git HTTPS/npm，以及经过代理的 WebSocket。手机网页访问电脑仍走 Wi-Fi，公开外网资源走蜂窝网络。电脑其他软件和另开的电脑浏览器不会自动改用手机流量。

请留意这些实际限制：

- 手机系统需要支持同时保持局域网 Wi-Fi 与移动数据。蜂窝出口**不经过手机 VPN**，移动数据本身必须能够访问所用 API。
- 手机模式只转发公网目的地；电脑本机 `localhost` 或局域网模型后端请使用「使用电脑网络」。自定义网络 Agent、绕过代理的插件、SSH/UDP 和独立外部程序不保证自动覆盖。
- 手机流量会正常消耗套餐；界面统计的是中转字节，包含局域网页面流量，不等于运营商计费流量。
- 后台保持会增加耗电。厂商省电、系统强制停止、网络断开、电脑休眠或服务重启仍可能截断回复；已取消的生成不能自动续传。
- 局域网连接没有额外增加 TLS。使用 HTTP 酒馆地址时，请在信任的局域网中使用；上游 HTTPS 保持原有证书校验，中转不解密内容。项目没有内置账号密码或 API 密钥。

## 构建与验证

安卓客户端使用原生 Java + 系统 WebView，电脑插件使用 Node.js。构建需 JDK 17 或 21、Android SDK API 35 和 Build Tools 35.0.0；Gradle Wrapper 使用 Gradle 8.9。

Windows PowerShell 在项目目录运行：

```powershell
.\build.ps1 -JavaHome $env:JAVA_HOME -AndroidSdk $env:ANDROID_HOME
```

脚本会构建 APK、运行单元测试和 Android Lint，并生成插件 ZIP；输出位于 `dist/`。也可直接运行 `gradlew.bat assembleDebug testDebugUnitTest lintDebug`。

1.3.3 已通过 **61 项 Android JVM 测试、33 项 Node.js 测试**、离线 HTTPS 转发测试、APK 构建与签名检查，Android Lint 为 0 errors / 5 warnings。双网络路由、自动配对和锁屏稳定性仍需真机验收，尚未完成各品牌安卓设备验证。测试方法见 [测试说明](tools/TESTING.md)，检查记录见 [VALIDATION.md](VALIDATION.md)。
