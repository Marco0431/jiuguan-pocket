该次 VPN 报告的底层传输为 **Wi-Fi**。这验证了手机 VPN 出口兼容性，**没有证明校园外网断开后、VPN 只靠流量的完整场景已经通过**。VPN 的底层网络由它和系统决定，酒馆口袋不能替其他 VPN 强制选流量。

新版路由验收应覆盖：

1. 没有覆盖酒馆口袋的活动 VPN 时，外网走蜂窝；有覆盖它的活动 VPN 时优先走该 VPN，酒馆局域网页面仍走 Wi-Fi。先在手机现有代理中启用该应用并允许局域网访问；本项目不内置节点、不读取代理配置。
2. 在「连接诊断」核对当前公网出口、VPN 报告的底层传输和局域网状态。不能把 VPN 图标存在、页面打开或 TLS 成功单独当成模型生成成功。
3. VPN 切换、暂时阻塞、网络能力回调延迟时，旧网络结果不能覆盖新选择；不得把仍存在但暂不可用的 VPN 静默回退为蜂窝直连。
4. VPN 为合法域名返回 `198.18.0.0/15` FakeIP 时可以连接；裸 FakeIP 目标、非 VPN 下的 FakeIP 和其他内网目标仍应被拒绝。对应地址策略和路由切换已有 JVM 回归。
5. 后续现场验收需让 Wi-Fi 保持局域网互通、断开它的外网，再确认手机代理确实经流量工作，重复普通回复、流式回复和锁屏测试。此项尚未完成，不可用前面的 Wi-Fi 底层 VPN 成功替代。

## 连接诊断与地址重试（1.3.3 起）

使用 1.3.4 APK 和至少 1.3.3 电脑插件后选择手机模式；首次安装或更新电脑插件才需要重启酒馆。重现模型列表或发送失败，再从「更多」→「连接诊断」→「刷新」→「复制诊断」取得报告。配置页亦可进入。诊断只读取状态，不调用真实模型，不刷新网页，不重发生成请求。

- 手机应分别列出局域网页面、电脑外网、页面外网的尝试和 TCP 成功次数；局域网页面打开不能被当作蜂窝 API 连通证据。
- 电脑报告应区分桥接格式错误、手机代理连接失败、HTTP 已转发／TCP 隧道建立和上游 HTTP 状态。HTTP 400 的具体来源仍应结合该轮实际报告判断。
- 报告允许包含目标域名，不应包含凭据、URL 路径、查询参数、请求头、原始异常或聊天内容。复制由用户主动点击。
- 关闭手机模式后，电脑应停止采集并保留上一轮计数；再次开启清零。手机计数为本次应用会话累计，两边不要求逐项相等。并发请求下“最近一次”不一定是失败的模型请求。
- 1.3.4 优先选择覆盖本应用的活动 VPN，没有时绑定蜂窝；报告显示当前选择及 VPN 报告的底层传输，但不据此保证所有 API 可达。
- 用不可达的首个 IPv6 和可达 IPv4 模拟地址回退，检查交错选择、每次至多 3 秒和 DNS 前开始的 12 秒预算。JVM 假时钟测试覆盖预算、去重、地址过滤和网络取消；仍需真实运营商网络验收。

电脑端离线 HTTPS 回归（不使用真实 API 密钥或模型）：

```powershell
$env:JIUGUAN_TAVERN_DIR = 'C:\SillyTavern' # 换成已安装依赖的酒馆目录
node .\tools\server-plugin-https-smoke.mjs
```

需要本机 OpenSSL，可使用 `--openssl` 或 `OPENSSL` 环境变量指定。测试使用酒馆实际的 `node-fetch`、Node 原生 `fetch`、运行时代理、HTTP/CONNECT 桥和认证 SOCKS 夹具，检查可信测试 TLS、模型列表 GET、大 POST、远端 DNS、模拟上游 400 与桥接错误的区别、隐私字段过滤和旧代理恢复。测试信任仅用于子进程，不更改系统信任设置；通过不代表真实手机双网络已验证。

## 真实酒馆服务、当前插件和 Java SOCKS 全链路

`tavern-e2e-smoke.mjs` 将实际酒馆程序复制到 `dist/` 下的临时目录，使用隔离配置和用户数据启动真实 `server.js`。它测试真实登录、CSRF、插件配对、模型列表、普通生成、延迟 SSE 流式回复，以及 Vertex AI Full/global 认证流程。它直接编译 App 的 `SocksProxyServer.java`，与当前插件一起运行；只将指定测试域名转发到本机假 API，不调用真实模型、不读取真实服务账号。

```powershell
node .\tools\tavern-e2e-smoke.mjs --tavern C:\SillyTavern --java-home $env:JAVA_HOME --openssl openssl
```

需要已安装依赖的酒馆、JDK 17+、OpenSSL，以及本机可用的私网 IPv4。可用 `--lan-address` 指定本机私网地址；端口 10808 必须空闲。为保留插件原有来源地址校验，测试临时监听该地址的 10808 和一个随机酒馆端口，使用随机认证凭据和仅本机地址的白名单；它不会关闭生产服务或修改系统代理。

Vertex 测试生成临时 RSA 测试账号，将 OAuth 和模型 API 的指定域名映射到本机 HTTPS 夹具，证书信任仅作用于隔离子进程。分别模拟认证成功、上游拒绝和连接中断，验证酒馆的实际响应与代理计数。它能揭示“认证网络失败被酒馆返回为 HTTP 400”，不能证明真实运营商网络可访问 Google。

退出时停止测试进程和监听，先移除依赖目录联接，再删除本次临时配置、账号和数据。需要检查真正的手机蜂窝选路、VPN、WebView 和后台保活时，仍须连接安卓真机；运行 Java SOCKS 核心不能替代这些 Android 系统行为。

## 基础网页与后台保持

本夹具仅用 Python 标准库，不连接 AI API。电脑运行：

```powershell
python .\tools\smoke_server.py --host 0.0.0.0 --auth
```

手机与电脑连同一局域网，在客户端选择「使用电脑网络」，填 `http://电脑局域网IP:8765/` 并点击「打开酒馆」。此 Python 夹具没有酒馆插件，不用于手机流量自动配对。系统如提示防火墙，可仅允许受信任的专用网络。安卓模拟器使用 `http://10.0.2.2:8765/`；默认不加 `--host` 时仅本机可访问。测试登录为 `test` / `test`，不使用酒馆真实密码。

1. 确认原生登录框正常；登录后页面完整、键盘不遮住输入框。
2. 开启后台保持，启动默认 180 秒测试，切回桌面并锁屏约三分钟，再打开客户端。页面应显示“完整完成：180/180”，服务终端应出现 `STREAM COMPLETE`。检查返回前后同一 session，没有重新发起测试。
3. 再次测试切到其他应用、旋转屏幕、从通知返回。服务端 `/sessions` 提供最多 100 条仅内存状态；重启服务全部清空。
4. 开始长测试后主动停止，终端应出现 `STREAM DISCONNECTED`（操作系统可能稍延迟发现断开）。客户端不应自动重试。刷新也不自动开始测试。
5. 在一次文件选择器操作中同时选择一张图片和一个 JSON 文件（`multiple`），确认两者都显示文件名；点击“下载 Blob JSON”，确认系统保存流程与内容。夹具在 `a.click()` 后立即撤销 Blob URL，与酒馆的导出行为一致。点击新窗口链接，确认可正常打开并返回。
6. 在真实酒馆启动一次短回复后重复后台/锁屏操作，检查最终回复完整保存。夹具通过不能替代各品牌真机、真实网络和酒馆的验证。

## 记住密码与自动登录验收（1.3.2 行为）

夹具使用 `--auth`，用户名和密码都是 `test`，无需真实酒馆密码。

1. 首次或从旧版升级后，先手动连接成功一次。确认登录框有「记住账号密码」「自动登录」，两项勾选并登录成功后退出应用进程再启动。应出现简洁自动连接等待页，按已验证地址和网络模式尝试一次，并在主站需要认证时自动提交账号。
2. 在「账号与自动登录」关闭自动登录，退出进程后重开。已验证连接仍会自动尝试一次，但原生登录框只预填账号，等待用户手动登录；不能因为关闭账号自动登录就丢失成功连接记录。
3. 清除账号密码，退出进程再启动并连接，应不再预填；默认不勾选记住，除非用户重新开启。当前已登录会话不会因清除操作立即退出，所以务必退出进程后测试。
4. 模拟服务端修改密码：重启夹具并用另一个测试服务要求新密码，再重开客户端。应最多自动提交一次，随后出现可编辑的登录框，不能无限循环重试。
5. 更换端口、协议或认证 realm，不应读取另一条账号记录；取消登录、主框架网络错误和 HTTP 错误均不能保存本次候选密码。
6. 通过调试包 `run-as` 检查 `encrypted_credentials_v1` 偏好文件：只允许看到版本化密文和地址/realm 索引，不应出现明文 `test` 账号密码；不要把真实密码写入测试记录。

`--seconds` 通过页面输入设置，每秒一个编号，范围 1–3600。服务默认端口 8765，可用 `--port` 修改。请勿将夹具暴露到公网；它是临时测试工具。

## 1.3.2 单次自动启动、连接取消与原生设置验收

以下是待执行的真机清单，不代表已经在安卓手机上验证通过。先使用电脑模式和 Python 夹具，再使用已安装插件的真实酒馆测试手机模式。

1. **首次验证与后续自动启动。** 新安装或旧版升级后没有成功记录时，应先显示原生「连接设置」，即使旧版保存了密码也不能直接认定连接有效。联网方式位于配置最上方：电脑能联网选电脑模式，电脑只有内网选手机模式并同时开启 Wi-Fi 与移动数据。手动成功连接后，记录实际通过验证的地址、网络模式与后台设置。停止进程再打开应自动尝试一次，显示等待页与「取消连接，修改设置」，无需再点打开。
2. **未验证的新设置。** 成功后改变地址、网络模式或后台设置并尝试连接，但未成功完成验证，停止进程再打开。新的未验证组合应回到配置界面，不应被当作成功配置自动使用；也不能把旧网页的成功回调记到新设置上。重新成功连接后再验证后续冷启动。
3. **错误 IP、未启动酒馆。** 手动测试格式合法但不可达的 IP、正确 IP 下未监听端口，再测试已有成功记录但电脑酒馆已关闭的自动启动。手动连接留在配置页，自动连接显示可取消等待页；失败或约 15 秒准备超时后均回到可编辑状态。本次启动不应在切回前台、旋转或收到晚到回调后再次自动重试。
4. **未开启移动数据。** 选择手机流量模式但关闭移动数据，分别测试手动及按成功记录自动启动。等待期间均能取消回设置，也应在准备超时后恢复可编辑。开启数据后由用户再次点打开；保留先前地址、模式和已保存账号，不重复发送生成 POST。
5. **Basic 登录暂停与取消。** 关闭账号自动登录，让原生 Basic 登录框在自动启动中出现。等待超过 15 秒，输入框不能被连接超时夺走。正确提交后继续完成加载；取消登录则回配置页并可修改。取消不能保存本次未验证的新密码，也不能清除原有已记住的凭据。
6. **网页登录页。** 对启用酒馆账号系统的测试实例，确认 `/login` 页面正常显示并允许用户完成登录。登录页不能被插件等待计时误判为普通成功页面；完成登录并确认所选网络模式后才可记录为验证成功的启动配置。
7. **插件确认时限。** 先成功使用手机模式，再测试自动启动时网页已加载但插件未回复。额外确认等待最多约 6 秒，然后应回到配置并说明原因；插件明确报错也应返回。缺插件、非管理员、手机配对失败等情形不得保存为成功的手机启动记录。插件及时确认后，旧确认计时器不能再次使连接失败。
8. **快速取消再连接。** 在自动等待页取消后改为正确设置手动打开。上一轮迟到的网络、网页、插件或超时回调不能取消新连接、覆盖新状态或把旧网页切到前台。重复几次，确认没有多个登录框或重复导航；切回前台不能再触发本次启动的自动尝试。
9. **成功后的旧超时。** 让连接和插件确认在各自时限内成功，之后继续等待至少 30 秒。旧计时器不能把成功页面退回设置、显示失败或断开当前会话。
10. **设置仅查看。** 网页成功后点击右侧「连接设置」，应直接出现原生设置页，原网页不能因此刷新。点「返回当前酒馆」，检查同一页面、同一测试 session 与未发送输入仍在。只有明确点击「应用设置并重新连接」才按新设置导航；该操作可能中断当前生成。检查「更多」菜单里的网络切换入口仍可直接切换。
11. **旋转与后台恢复。** 分别在自动连接等待、Basic 输入、取消后配置页和成功网页中旋转设备；回前台后保留当前状态，不增加自动连接次数或生成请求。已有成功会话从后台或通知直接恢复同一个 WebView，不 reload；进程重建后才按已验证配置尝试一次新的页面连接。

记录每项实际手机型号、安卓/WebView 版本、等待时间和结果；重点检查「失败可改、等待可取消、成功不被旧回调打断」。

## 1.3.2 自动配对与手机流量验收

自动检查（不调用真实模型）：

```powershell
.\build.ps1
$env:JIUGUAN_TAVERN_DIR = 'C:\SillyTavern' # 换成已安装依赖的酒馆目录
node --test .\tools\phone-relay.test.mjs
node --test .\tools\server-plugin.test.mjs .\tools\server-plugin-install.test.mjs
node .\tools\relay-integration-smoke.mjs --tavern $env:JIUGUAN_TAVERN_DIR
```

Node 测试使用外部 SillyTavern 安装的依赖，本仓库不包含酒馆或其 node_modules。最后一个检查使用真实 Java SOCKS 核心、酒馆依赖和临时本机 HTTP/HTTPS 流式服务器；需要本机 JDK 和 OpenSSL，会在临时目录生成测试证书并在退出时清理。可用 `--java-home` 和 `--openssl` 指定工具路径。测试证书只信任于测试客户端，不修改系统信任设置。

安装器测试只操作临时模拟酒馆目录，检查配置注释保留、备份、失败回滚和重复安装，不修改实际酒馆。服务端测试覆盖权限、配对、切换竞态、取消操作、原代理恢复和本机网络夹具；自动检查不能替代真实手机双网络验证。

真机准备：「电脑仅内网，手机同一 Wi-Fi + 移动数据」。在电脑安装一次配套插件，重启后照常使用原来的 `Start.bat`；不要同时使用旧版手机代理启动器。Node.js 需支持运行时代理切换（24.14+ 或 25.4+），多用户酒馆使用管理员账号，保留 CSRF 保护。实际酒馆安装步骤见 [一次性插件安装说明](SERVER-PLUGIN-INSTALL.md)。

1. **两种模式与自动配对。** 确认原生首页和网络设置都只有「使用电脑网络」「使用手机流量」这两种模式，选择状态一致。首次选手机模式后手动打开酒馆并登录，网页成功且电脑插件确认后才记录成功配置；之后冷启动自动尝试一次该配置。整个流程不应要求复制或粘贴代理 URL。记录等待提示、成功状态及发送/接收计数。未连接 Wi-Fi 或未开启移动数据时不能显示已连接。
2. **登录和权限错误。** 分别检查未安装／未启用插件、安装后尚未重启、非管理员登录、错误密码、登录过期和不兼容 Node.js。应显示可理解的失败原因，不误报切换成功。修复后手动重新连接应可继续；错误密码不能自动循环提交。保留前面的记住密码与自动登录验收。
3. **电脑离线访问外网。** 电脑仅保留局域网连接后，依次测试模型列表、一次短回复、标准 HTTPS 资源下载、Git HTTPS 扩展下载，以及网页公开 HTTPS 图片。确认外网通过手机，电脑不需要外网 DNS；手机控制配对成功本身不能证明运营商网络可访问具体 API。真实 AI 生成会使用所配置服务的额度，先完成无 AI 夹具测试再进行。
4. **恢复电脑原网络。** 在测试环境预先设置可辨识的电脑代理配置，选择手机模式，再选择电脑模式并等待确认。检查电脑进程原代理、原生 fetch／默认 HTTP Agent 行为和相关环境已恢复，Windows 系统代理及酒馆持久代理配置没有被切换过程改写。电脑模式下原有 localhost／局域网模型后端应可用；手机模式下这些后端应明确失败，不得偷偷绕过公网目的地限制。
5. **快速切换与过期响应。** 通过网页「更多」中的网络设置快速执行「手机 → 电脑 → 手机」及「手机 → 电脑」。在原生首页连接等待时，先取消再选择新模式重连。最终状态必须服从最后一次选择；较早的成功响应不能把电脑重新切回手机模式。成功切到电脑模式后，网页继续可用，不残留失效的本机网页代理。重复点击同一模式不应创建多套中转。
6. **电脑重启后同步。** 手机保持手机模式、局域网和有效登录，重启电脑酒馆并照常使用 `Start.bat`。记录下一个约 60 秒状态同步周期及连接耗时，确认插件重新配对后新请求可用。若登录失效，应提示重新登录。同步只能更新连接控制状态，不自动刷新页面或重发上一轮生成。
7. **手机断网与 IP 变化。** 流式回复中关闭移动数据，原连接应失败；恢复后等待重新就绪，再由用户发起新的请求。重复测试 Wi-Fi 断开、重连及手机 LAN IP 改变，确认自动配对使用新地址，无需 `--configure` 或手动粘贴。检查关闭网络后收到的旧回调不能重新启用已关闭的模式。
8. **后台和锁屏。** 开始流式回复后切后台、锁屏并从通知返回，检查回复、计数及存档。记录手机型号、安卓版本、WebView 版本、厂商电池设置和持续时间。省电策略或蜂窝网络仍可能截断；不得将一次通过写成所有机型保证。
9. **停止与恢复失败。** 从已打开网页切换电脑模式，再测试「停止并断开」。确认成功确认前后的状态准确；电脑暂时不可达时应保留恢复待处理提示，连接恢复后再次同步。关闭整个会话后，手机中转监听、通知和 Wi-Fi／CPU 锁应释放，不会因迟到的准备回调重新启动。
10. **禁止自动重复生成。** 对冷启动自动连接、网络切换、快开关、电脑重启、移动数据恢复、Wi-Fi IP 变化及插件控制超时分别记录生成接口请求数。自动启动只能连接页面和认证，不能恢复上一轮模型请求；仅用户明确生成时发送新的生成 POST。后台可以重试幂等的插件控制操作，但不得重放聊天生成、刷新后自动继续或恢复已取消的请求。

1.3.4 手机模式优先使用覆盖本应用的活动 VPN，没有时使用蜂窝网络；VPN 的底层网络选择由 VPN 和系统决定。手机中转以公网目的地为限，仅为合法域名在所选 VPN 内返回的 FakeIP 增加限定兼容，因此 localhost／局域网模型后端仍应使用电脑模式。第三方插件自定义 Agent、绕过代理、UDP、SSH Git 或独立外部程序不保证自动覆盖；另开的电脑浏览器也不在范围内。网页渲染仍在手机，酒馆服务和数据仍在电脑。旧 `start-phone-relay.cmd` 流程只作历史兼容，当前验收以插件自动配对为准。
